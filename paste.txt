## Required architecture

### A. Secure student identity

The frontend must NOT provide a trusted `studentId`.

The flow should be:

```text
Next.js
→ authenticated request
→ NestJS verifies existing user JWT/session
→ NestJS obtains authenticated student/user ID
→ NestJS securely sends the identity to FastAPI
→ FastAPI verifies that internal request
→ student-specific data is fetched
```

Prefer using the project's existing authentication infrastructure.

If appropriate for the existing codebase, NestJS may generate a short-lived internal JWT for FastAPI containing:

```text
sub = authenticated student/user ID
purpose = aria-chat
short expiration
issuer = SISP backend
audience = SISP ML service
```

Do not introduce this mechanism if the project already has a secure internal authentication mechanism that is better suited.

Never trust a student ID supplied directly in the chat request body.

### B. Multi-question handling

Support questions such as:

```text
"When is enrollment, how much is my balance, and what is my schedule tomorrow?"
```

Add a multi-intent orchestration layer.

Target flow:

```text
Language Detection
→ Moderation
→ Scope Gate
→ Authentication / Student Context
→ Question Segmentation
→ Intent Classification per segment
→ Route every detected intent
→ Retrieve required information
→ Aggregate results
→ Generate one final response
→ Existing escalation/confidence handling
```

Do not destroy the current single-intent classifier.

Initially, reuse the current classifier by classifying each detected sub-question individually unless inspection shows that another approach fits the codebase better.

Example:

```text
"How much is my balance and what is my schedule tomorrow?"

→ student_balance
→ student_schedule
```

Each result must maintain its own:

* intent
* confidence
* source/type
* retrieved data
* errors or escalation status

### C. Data-source routing

Separate institutional knowledge from student-specific information.

Use RAG/knowledge-base retrieval for questions such as:

```text
"What are the enrollment requirements?"
"What is the payment policy?"
"When does enrollment start?"
```

Use authenticated PostgreSQL/Supabase data for questions such as:

```text
"What is my schedule?"
"What subjects am I enrolled in?"
"What is my enrollment status?"
"What is my balance?"
```

Implement a student-context service or equivalent reusable layer.

Start with:

```text
get_student_schedule(authenticated_student_id, date/day filters)
```

Design it so these can be added later:

```text
get_student_balance()
get_enrollment_status()
get_enrolled_subjects()
get_grades()
get_student_profile()
```

### E. Combined response



Do not let failure of one sub-question automatically discard successful results from the other sub-questions.

### F. Security requirements

* Never trust `studentId` from the frontend.
* Use authenticated identity from the existing backend authentication layer.
* Validate NestJS → FastAPI internal requests.
* Use parameterized ORM/database queries.
